# 免费数据源手册

你以为要付费数据终端才能拿到的东西——公司级信用违约互换(CDS)利差、央行日频利率、
交易所级别的融资余额与强制平仓、AI 模型用量份额——这里全部是免费公开、零鉴权(或
"填个假 demo key 就能用")的官方/一手接口。本文档逐条记录:端点、参数、编码坑、
口径坑、失效风险。这是本仓库的核心资产,建议先读这份再看脚本代码。

> 通用免责:所有端点都是第三方或官方公开接口,截至本文档编写时实测可通,但接口随时
> 可能改版、限流或需要重新验证。脚本自带的报错/留空逻辑会告诉你哪条腿断了,断了就先
> 来这份手册里对照排查。

## 1. KOFIA FreeSIS —— 韩股融资余额 + 强制平仓

**端点**:`POST https://freesis.kofia.or.kr/meta/getMetaDataList.do`

**参数**(JSON body):
```json
{"dmSearch": {"tmpV40": "1000000", "tmpV41": "1", "tmpV1": "D",
              "tmpV45": "起始日YYYYMMDD", "tmpV46": "结束日YYYYMMDD", "OBJ_NM": "对象代码"}}
```
两个对象代码,各自返回列的含义要对着 `/meta/getSrvData.do` 的元数据表才能核对清楚
(接口本身不带列名,只给 `TMPV1`/`TMPV2`… 这种位置化字段名):

- `STATSCU0100000070BO`(信用供与余额):TMPV1=日期,TMPV2=信用融资合计,TMPV3=主板
  (유가증권),TMPV4=创业板(코스닥),TMPV5-7=信用借券卖出(대주),TMPV8=打新贷款,
  TMPV9=存托证券担保融资
- `STATSCU0100000060BO`(股市资金):TMPV1=日期,TMPV2=投资者预托金(客户保证金,不含
  场内衍生品),TMPV3=场内衍生品预收金,TMPV4=对客户RP卖出余额,TMPV5=委托未收金
  (미수금),TMPV6=对前日未收金的实际강제매매金额,TMPV7=未收金对比强平比重(%)

**编码坑**:纯 JSON API,UTF-8,没有编码问题——坑在别处。

**口径坑**:
- 单位是百万韩元(因为 `tmpV40=1000000`);比重列是百分比,不是小数
- 강제매매(强制平仓)是"对前一日未收金"执行的,不是对当日——暴跌日 D 当天的强平潮会
  体现在 D+1、D+2 的数据里,别在暴跌次日就下结论说"没有强平潮"
- 官方脚注写明 2023-10-25 起改为按"체결금액"(成交金额)口径统计强平金额,新旧口径
  绝对水平不可比,做历史对比/回测必须分段处理
- 这个强平口径只覆盖"未收金"(T+2 透支买入)触发的强平,不含券商信用融资维持率不足
  触发的追加保证金强平——后者没有公开的日频集中数据源

**失效风险**:截至编写时,公开可查范围内没有找到这条取数管道的开源实现或公开教程。
好处是没人跟你抢;风险是接口一旦改版没有社区能帮你快速找到替代方案,得自己重新抓包。
本机在美国 IP 下实测直连成功,理论上有被限制到仅韩国 IP 访问的风险(未观测到,留作
已知风险提示)。

## 2. Naver 海外股票 API —— ADR/海外上市股票现价

**端点**:`GET https://api.stock.naver.com/stock/{TICKER}{后缀}/basic`

**参数**:后缀取决于交易所——纳斯达克上市通常是 `.O`,纽交所上市通常是 `.K`。具体
代码去 Naver 海外股页面(`m.stock.naver.com/worldstock`)搜一下目标 ticker,URL 里
带的代码就是要用的格式。

**编码坑**:返回标准 JSON,UTF-8,无坑。

**口径坑**:`closePrice` 字段在美股盘中时是最新价(不是严格意义的"收盘价"),脚本里
只在"美股已收盘"的时间窗口调用,当收盘价用;如果你在盘中跑,拿到的其实是最新成交价。

**失效风险**:这是 Naver 网站前端调用的内部 API,不是对外公开宣称的开放接口,理论上
可能不打招呼就改版或加限制。截至编写时无需鉴权、无需 Referer 校验。

## 3. Naver 个股资金面页(frgn.naver)—— 韩股逐日收盘 + 机构/外资净买

**端点**:`GET https://finance.naver.com/item/frgn.naver?code={6位股票代码}`

**参数**:`code` 是 KRX 6 位数字代码(如 `000660`)。返回的是 HTML 页面,不是 JSON——
脚本用正则把 `<tr>` 行拆开解析,不是调用什么干净的 API,这是这条通道最脆弱的地方
(Naver 改一次页面结构,正则就要跟着改)。

**编码坑**:页面声明的是 **cp949**(韩文 Windows 编码),不是 UTF-8,也不是 GBK/GB2312
——拿 UTF-8 硬解会得到乱码或直接抛异常。Python 里用 `.decode('cp949', errors='ignore')`。

**口径坑**:
- 机构净买/外资净买的单位是**股数**,不是金额,自己按当日收盘价折算成金额
- 当日盘中看到的是"前一日为止"的定版数据,当日的真实数据要等 Naver/KRX 盘后处理完成
  (经验上韩国当地时间 18:00 之后)才会出现在页面上
- 外资持股率是快照式的比例,不是净买卖量,别混着算

**失效风险**:纯网页刮取,没有官方 API 承诺的稳定性;Naver 页面结构变了脚本会直接
解析不出数据(空列表),不会静默返回错误数字——这是本仓库所有页面刮取类脚本共同的
设计原则:宁可拉不到也不编数。

## 4. Naver 汇率页 + open.er-api.com —— 外汇汇率

**端点**:
- 主源(仅 USD/KRW 这一对):`GET https://finance.naver.com/marketindex/`(HTML,正则
  抓 `FX_USDKRW` 后面的 `<span class="value">` 数值)
- 备源(任意货币对,免费无需注册):`GET https://open.er-api.com/v6/latest/{BASE三位代码}`
  返回 `{"rates": {"KRW": 1234.5, "JPY": ..., ...}}`,任意目标货币代码去 `rates` 里取

**编码坑**:Naver 页面同样是 cp949;er-api.com 是标准 UTF-8 JSON,无坑。

**口径坑**:两个源都是"取数时点即期汇率",不是某个交易日的官方定盘价(如 WM/Reuters
16:00 伦敦定盘)。跟需要精确到当日某个时点汇率的场景(比如跟财报里的汇率注释对账)
会有小时级偏差,当日常监测的温度计足够,精算场景需要换成有定盘时点的汇率源。

**失效风险**:er-api.com 是免费层服务,理论上有请求频率限制(本仓库的调用频率是
每标的每天 1 次,远低于任何合理限流阈值)。

## 5. OpenRouter 排行榜 API —— 全球 AI 模型 Token 用量

**端点**:`GET https://openrouter.ai/api/frontend/v1/rankings/models?view=day`

**参数**:`view` 取值 `day`/`week`/`month`。

**编码坑**:标准 JSON,UTF-8,无坑;但接口偶尔会被 Cloudflare 之类的前置挡住裸
`urllib` 请求,脚本默认优先用 `scrapling`(伪装浏览器指纹)抓取,失败了才退化到裸抓。

**口径坑(最重要的一条)**:`view=day/week/month` **不是"当日/当周/当月"的独立统计
口径,而是统一的拖尾累计窗口**——每个模型一行,日期字段挂的是"该模型最后活跃的日期"。
换句话说:
- `view=week`、`view=month` 返回的是**累计和**,还混着已经掉出榜单的"死模型"残留行
  (日期早于主体日期一大截),**不能当逐日序列拆分使用**
- 真正的逐日序列只能靠每天单独调一次 `view=day`,漏跑一天就永久缺那一天,没法用
  week/month 事后拆解补回来
- 想要某个模型过去 31 天的真实逐日数据,得换用单模型接口
  `GET /api/frontend/v1/stats/model-activity?permaslug={模型slug}&variant={变体}`——
  但这个接口只能查"当前仍在榜"的模型,已下架模型的历史查不到,`--backfill` 模式用的
  就是这条路径,补出来的早期总量会因此略微低估(下架模型的历史贡献缺失)
- 统计的 Token 口径是 `prompt + completion`,不含 `reasoning` 单列字段(该字段在
  编写时的样本里普遍是 0,以后可能变化,自己留意)
- 这是"该平台上的用量",不是全球 AI 推理总量,也不包含各厂商自家应用(ChatGPT 网页版、
  Claude.ai 等)的直连流量——只能看趋势和份额变化,不能当总量的绝对值引用

**失效风险**:非公开宣称的稳定 API(前端专用接口),厂商国别映射(CN/US/other)靠脚本
里维护的白名单,新模型上线需要人工补充映射,占比超过 1% 时脚本会在输出里提醒你去补。

## 6. ICE Clear Credit —— 公司级 5 年期 CDS 结算价

**端点**:`GET https://www.ice.com/api/cds-settlement-prices/icc-single-names`

**参数**:无参数,一次性返回全部已清算单名 CDS 的当日结算价,自己在返回结果里按
`name`/`instrumentName` 过滤想要的公司。

**编码坑**:标准 JSON,UTF-8;但接口对请求头比较挑剔,裸 `urllib` 有时会被拒绝,建议
用 `scrapling` 的浏览器指纹伪装(`impersonate='chrome'`)。

**口径坑**:
- `instrumentName` 格式是 `TICKER.分层.币种.文档类型.票息bp.到期日`(如
  `ALPHINC.SNRFOR.USD.XR14.100.2031-06-20`),公司名匹配要对 `name` 字段做正则,不是
  对 `instrumentName`
- 返回的 `eodPrice` 是**价格**(占面值百分比),**不是利差**。换算成利差用近似公式:
  `利差bp ≈ 票息bp − (价格−100)×100/久期`,本仓库固定用 5 年期风险久期常数 4.55——
  这是**近似口径**,跟专业终端(如 Bloomberg CDSW)算出来的精确利差会有小偏差,能看
  方向和历史分位,不能拿去跟精确报价逐点核对
- 价格跌 = 利差走阔 = 市场认为信用风险上升
- 只筛 `SNRFOR`(高级无担保债务)+ `USD` 计价,到期日取全场出现次数最多的那个(即
  当前 5 年期 on-the-run 桶),票息优先取 100bp 档(市场惯例的标准票息)

**失效风险**:ICE Clear Credit 是持牌清算所,这条数据是其监管披露义务的一部分,稳定性
预期较高;但仍是"每日免费公开页面",不是签了协议的数据服务,格式变化的风险自己留意。

## 7. 韩国央行 ECOS —— 利率与流动性代理利差

**端点**:`GET https://ecos.bok.or.kr/api/StatisticSearch/sample/json/kr/1/10/{统计表代码}/D/{起始}/{结束}/{科目代码}`

**参数**:demo key 固定用字符串 `sample`(零注册,不需要申请自己的 key,但配额未知,
遇到限流会优雅截断已拉到的部分,重跑自动续)。关键统计表/科目组合:
- `817Y002`(日频市场利率表):`010901000`=KOFR,`010150000`=KORIBOR 3M,
  `010502000`=CD 91天,`010503000`=CP 91天,`010210000`=国债 10年
- `722Y001`(基准利率表):`0101000`=央行基准利率(阶梯函数,只在调整日给值,平时
  向前结转)

**编码坑**:标准 JSON,UTF-8,无坑。

**口径坑**:
- demo key 单次最多返回 10 行,拉长区间必须分批翻页(脚本已处理,每批 10 天/次向前
  滚动)
- 基准利率是阶梯函数(只在央行议息调整当天才有新值),ECOS 只在变动日给数据,其余
  日期要自己向前结转(carry forward),脚本已处理
- 本仓库监测的不是"市场利率的绝对水平",而是三条**自建代理利差**:KOFR−基准利率
  (回购资金面松紧)、KORIBOR3M−基准利率(银行间利率,含加息预期成分)、CP91−CD91
  (非银 vs 银行的信用分层利差)。这三条利差是为了替代专业终端才有的 OIS 利差
  (KOFR-OIS / KORIBOR-OIS / CP-OIS)搭的代理,**口径不同,不能跟专业终端的利差数字
  直接比较绝对水平**,只能看自己历史序列内部的方向和分位

**失效风险**:demo key 的配额上限官方没有公开说明,回填历史时如果中途被限流,脚本会
优雅保留已拉到的部分并在下次运行时接着补,不会报错崩溃。

## 8. vast.ai Bundles API —— GPU 现货租赁报价

**端点**:`GET https://console.vast.ai/api/v0/bundles/?q={URL编码的JSON查询}`

**参数**(查询 JSON 示例):
```json
{"verified": {"eq": true}, "rentable": {"eq": true}, "num_gpus": {"eq": 1},
 "gpu_name": {"in": ["A100 SXM4 80GB", "H100 SXM", "..."]}, "type": "ask", "limit": 800}
```
`type: "ask"` 拿的是"已验证机器的报价挂单"(verified ask),不是所有挂单,这样质量
更可控。

**编码坑**:标准 JSON,UTF-8,无坑。

**口径坑**:返回的是**挂单价格分布**,不是成交价——脚本取这个分布的最低价和中位数
(`vast_min_dph`/`vast_med_dph`),真实成交价可能因为竞价、机器可用性等因素与挂单价
有差异。样本量(`vast_n`)是判断这个价格是否有代表性的关键,单卡型样本太少时数字
噪声会很大。

**失效风险**:公开接口,免鉴权,截至编写时无限流问题。这是 vast.ai 网站前端调用的
接口,不是官方文档化的公开 API,理论上可能改版。

## 9. RunPod GraphQL API —— GPU 云厂商定价

**端点**:`POST https://api.runpod.io/graphql`

**参数**(GraphQL query,无需鉴权即可查询公开定价):
```graphql
{ gpuTypes { displayName securePrice communityPrice } }
```

**编码坑**:标准 JSON,UTF-8,无坑。

**口径坑**:`securePrice`(安全云,数据中心级)和 `communityPrice`(社区云,个人/小型
机房挂机)是两个不同的可靠性/合规层级,价格通常有明显差异,报的时候两个都要给,别
只挑便宜的那个说。

**失效风险**:公开 GraphQL 端点,这条 query 不需要 API key;RunPod 的付费类查询
(账户余额、实例管理等)需要鉴权,与本脚本用到的公开定价查询无关。

## 10. Google News RSS —— 关键词新闻监听

**端点**:`GET https://news.google.com/rss/search?q={URL编码查询}&hl={界面语言}&gl={地区}&ceid={地区:语言}`

**参数**:`q` 支持 Google 搜索语法的子集——`OR`、双引号短语匹配、括号分组都可用
(如 `HBM (NVIDIA OR 엔비디아) (qualification OR "market share")`)。`hl`/`gl`/`ceid`
控制返回结果的语言与地区侧重(不是严格过滤,只是排序权重不同)。

**编码坑**:返回标准 RSS/XML,UTF-8,用标准库 `xml.etree.ElementTree` 解析即可,无坑。

**口径坑**:Google News 的搜索匹配比字面语法宽松,经常会混入语义相关但不完全符合
查询词的条目(比如查 HBM 相关新闻,偶尔会混进泛半导体新闻)。本仓库脚本额外加了一层
客户端标题关键词过滤(`must_contain`)兜底,但这只能挡掉明显不相关的,不能保证 100%
精确。信息本身的可信度分级(公司公告 / 研究机构 / 媒体报道)完全需要人工或 AI 判读,
脚本只负责去重和传输。

**失效风险**:这是 Google News 面向普通用户的 RSS 订阅功能,非签约的商业数据 API,
理论上有被限流或格式调整的风险,但作为公开可订阅的 RSS 源,历史上相对稳定。

## 11. investing.com 波动率指数页(可选手动源,无配套脚本)

**端点**:在 investing.com 站内搜到目标股指波动率指数,页面 URL 形如
`https://www.investing.com/indices/<指数slug>`——各主要市场的股指大多有对应的波动率
指数,页面结构相同,一套抓法通用。

**抓法**:页面对裸 `urllib` 有反爬,用 `scrapling` 的 `Fetcher.get(url, impersonate='chrome')`
伪装浏览器指纹可通;拿到 HTML 后正则抓 `data-test="instrument-price-last"` 属性后面的
数字,就是页面当前显示的最新值。

**口径坑**:抓到的是"最新值"——盘中抓是实时读数,要收盘口径就得等对应市场收盘后再抓。
首次接入一个新的波动率指数,建议先跟该指数发布方(交易所)官网的数值核对一次,确认
页面数据没有偏差,再开始攒历史序列。

**失效风险**:纯网页刮取,`data-test` 属性名或页面结构一改正则就失效;investing.com
的反爬策略也可能收紧,届时换抓取方案或换源。

## 12. 杠杆ETF对理论日变动的偏离(可选手动源,无配套脚本)

**方法**(不是一个端点,是一个自算指标):杠杆 ETF/ETP 的理论日变动 = 倍数 × 标的当日
涨跌%;偏离 = 实际涨跌% − 理论值,单位记 pp。持续且方向一致的偏离,往往反映该产品的
申赎资金压力、做市商对冲成本或跟踪机制问题,可当筹码/情绪层的辅助温度计。

**取数**:两条腿都只需要日涨跌幅,任何免费行情源都够——比如本手册第 2 条的 Naver
海外股 API(返回 JSON 里的 `fluctuationsRatio` 一类字段就是当日涨跌%),或第 3 条的
frgn 页。

**口径坑**:跨市场上市的杠杆产品(产品挂在 A 市场、标的在 B 市场)存在收盘时段错位——
两地收盘时间不同,各自"当日涨跌幅"覆盖的时间窗根本不重合,直接相减算出的"偏离"里
混着时差因素。读数要先排除时差(统一对齐到标的市场的收盘时点,或只在两地交易日完整
重叠的日子做比较),再谈资金面含义,否则会把纯粹的时间窗错位误读成申赎异动。

**失效风险**:方法本身无失效问题,风险跟随你选用的行情源(见对应条目)。

## 通用坑位小结

- **编码**:韩国相关的网页刮取(Naver 系)几乎全是 cp949,不是 UTF-8;API 类接口
  (JSON/XML)基本都是 UTF-8
- **反爬**:OpenRouter、ICE 两个接口对裸 `urllib` 请求偶尔挑剔,用 `scrapling` 的
  浏览器指纹伪装绕过;其余接口裸 `urllib` + 一个像样的 User-Agent 头就够
- **定版延迟**:几乎所有"当日数据"都有几小时到大半天的定版延迟,盘中/收盘刚过看到
  的数字大概率是临时值或上一交易日的值,详见各脚本文档字符串里的具体时间窗口
- **不编数原则**:本仓库所有脚本遵循同一条规矩——任何一条腿拉不到就报错留空,不用
  插值/估算/上一次的值顶替,宁可"待填"也不编数

## 2026-08 增补:新通道与新坑(实测)

> 以下为 2026 年 8 月实盘运行中新验证的通道与新踩的坑,增补于原手册之后,原文未改。

### 新通道

- **CFM 闪存市场(chinaflashmarket.com)**:存储现货报价——NAND Wafer(日频)、DRAM 颗粒与服务器内存条(周频),中文页面,报价带日期。坑:报价日期与页面更新日期是两回事,登记以报价日期为准;与 DRAMeXchange 口径不同,**两源永不混拼进同一条时间序列**(备源只做降级,不做混用)。
- **韩国关税厅出口旬报(korea.kr 搜索通道)**:半导体/存储出口旬报(每月 11/21 日前后)与月报,是公司收入的领先指标(领先 1 周-1 月)。坑:发布日期按 KST——跨时区脚本的搜索窗口要 +1 天兜住,否则 KST 上午发布的会整轮漏抓。
- **CNBC restQuote(quote.cnbc.com/quote-html-webservice/restQuote/...)**:美股实时报价兜底,一次多代码,含盘前盘后状态。非官方公开接口,只当兜底。
- **yfinance(Python 库,原手册未列,作历史/基本面通道补录)**:全球日线历史、基本面、一致预期。坑:①429 限流常见,沙箱/共享 IP 更甚;②**曾出现 chart 端点整日冻结在前一交易日且静默回吐旧数据**——不报错、数据看着正常,识别法是核对返回的 regularMarketTime 与当前时间差;③不当盘中实时源用。

### 老通道新坑

- **Naver 日线端点(krx_flow 相关)**:当日行情字段出现过"跌停价占位符"级脏数据(开盘价/最低价=精确等于 -30% 跌停价);另外不同端点对同一天的成交量口径可能不一致(临时值窗口内相差近一倍)。对策:关键读数双源核;**收盘定版前不下量能判读**。
- **ICE CDS**:端点只返回当日结算快照,**缺跑的日子是永久空洞**,无法回补——要么每交易日跑,要么接受序列断点并如实标注。
- **强制平仓(KOFIA)读法提醒**:强平对"前一日未收金"执行,比暴跌滞后 1-2 个交易日,暴跌次日别急着说"没有强平潮"。

### 增补二:两条方法型路标(脚本待仓库后续版本收录)

- **存储现货价(DRAMeXchange,dramexchange.com)**:DRAM 现货指数页有场次日期,DDR4 可对免费月度合约表算"现货-合同价差"(注意错期口径:免费合约锚更新滞后,价差先当现货动量用);NAND Wafer 各容量分列。与 CFM 二选一为主源,永不混拼。
- **市场级外资周排位(韩股)**:用交易所逐日投资者别净买卖(见 krx_flow 路标)按周聚合,再对 2005 年以来的全部完结周排位——"本周外资动作在历史上算多大事"比"外资今天买了多少"信息量大一个量级;进行中的周标"临时,N 个交易日",周五收盘后定版。同法可做散户对敲承接比(散户净买/外资净卖)。
- **时间序列宽表实践**:所有指标进一张按日宽表(一列一指标,2005 起),与判读快照分工——快照管当日判读,宽表管历史曲线与趋势三点(今日/一周前/一月前),电子表格直开可视。
